1. Lire ce document

Seule l'API (dépôt cetic-mezesse-backend) parle à la base : le site web et l'application mobile passent par elle. L'API utilise JPA avec Hibernate, qui écrit le SQL à partir des entités Java et des méthodes des dépôts (repository/). Ce document donne, pour chaque requête, ce qu'elle fait, quand elle s'exécute (action dans l'application et route de l'API) et son SQL.

Comment lire le SQL

  • Noms entre guillemets. Les tables et les colonnes gardent leurs majuscules ("Classe", "anneeId") : PostgreSQL exige alors des guillemets. Les noms tout en minuscules (nom, id) s'en passent.
  • Paramètres. :anneeId, :ids… sont les valeurs fournies par l'application ; Hibernate les envoie comme paramètres (?), jamais collées dans le texte, ce qui empêche toute injection SQL. IN (:ids) reçoit une liste.
  • Forme simplifiée. Le SQL est écrit pour être lu : SELECT * remplace la liste des colonnes qu'Hibernate énumère, et les alias sont courts. Les conditions, tris et colonnes écrites sont celles qu'envoie l'API. Pour quelques recherches par clé étrangère (compter les notes d'une matière, lire les notifications d'un compte…), Hibernate passe par une jointure sur la table liée et filtre sur son id au lieu de filtrer la colonne directement : le résultat est le même.
  • Identifiants. Les identifiants (id) sont générés par l'application (format cuid, par exemple cmvdtysczlku7c13ej18jpaub), pas par la base.
  • Énumérations. Le rôle (PROVISEUR pour le Directeur, SURVEILLANT_GENERAL, PROFESSEUR), le statut d'une inscription (ACTIF, RENVOYE), le sexe (M, F) et le type de barème (GRADE, COTE) sont des types énumérés PostgreSQL.

Ce qu'Hibernate ajoute de lui-même

  • Chargements groupés. Quand une page affiche des objets liés (le professeur de chaque matière, l'année de chaque classe…), Hibernate les lit d'un coup, jusqu'à 100 à la fois : SELECT * FROM "Utilisateur" WHERE id = ANY(:ids). Cela vaut pour toutes les tables et n'est pas répété dans chaque section.
  • Mises à jour complètes. Un UPDATE réécrit toutes les colonnes de la ligne, même celles qui ne changent pas.
  • Transactions. Chaque action de l'utilisateur s'exécute dans une transaction : toutes ses requêtes réussissent ensemble, ou aucune n'est gardée (chapitre 15).

Comment ce document a été vérifié

  • Chaque requête a été soumise à PostgreSQL avec EXPLAIN sur une copie de la base : syntaxe, tables, colonnes et types sont corrects (150 sur 150).
  • Le SQL réellement envoyé par l'API a été enregistré pendant un parcours de toutes ses routes (lectures, écritures, envois de fichiers, désapprobations) ; chaque instruction enregistrée correspond à une requête de ce document.

3. Comptes et connexion

Un compte par personne : le Directeur (rôle PROVISEUR dans la base), le Surveillant Général et les professeurs. Le mot de passe n'est jamais stocké en clair : la colonne motDePasse contient son empreinte bcrypt.

Tables : Utilisateur

Lire

Lire R1. Trouver le compte qui se connecte

Quand : Connexion (POST /api/auth/connexion). Le même identifiant peut être un e-mail ou un téléphone.

SELECT * FROM "Utilisateur" u
WHERE u.email = :identifiant OR u.telephone = :identifiant
ORDER BY u."creeLe";

Lire R2. Lire un compte par son identifiant

Quand : À chaque requête authentifiée (le compte du jeton doit encore être actif), puis dans la plupart des actions qui concernent une personne : Mon profil, fiche d'un enseignant, carrière, attestation, désapprobation.

SELECT * FROM "Utilisateur" WHERE id = :id;

Lire R3. Lister tous les comptes

Quand : Liste des personnels sans filtre (GET /api/utilisateurs), par exemple pour choisir le bénéficiaire d'une attestation.

SELECT * FROM "Utilisateur" ORDER BY role, nom, prenom;

Lire R4. Lister les comptes d'un rôle

Quand : Page Enseignants (GET /api/utilisateurs?role=PROFESSEUR) ; titre « Directeur » ou « Directrice » imprimé sur les documents (rôle PROVISEUR).

SELECT * FROM "Utilisateur" WHERE role = :role ORDER BY nom, prenom;

Lire R5. Compter les comptes actifs d'un rôle

Quand : Statistiques de l'établissement : nombre d'enseignants.

SELECT count(*) FROM "Utilisateur" WHERE role = :role AND actif = true;

Lire R6. Savoir si un compte de ce rôle existe

Quand : Amorçage d'une base vide : le Directeur et le SG ne sont créés qu'une fois.

SELECT u.id FROM "Utilisateur" u WHERE u.role = :role LIMIT 1;

Lire R7. Vérifier qu'un téléphone est libre

Quand : Création d'un enseignant, modification de sa fiche, Mon profil : un téléphone ne sert qu'à un seul compte.

SELECT * FROM "Utilisateur" u
WHERE u.id <> :id AND u.telephone = :telephone
LIMIT 1;

Lire R8. Vérifier qu'un e-mail est libre

Quand : Mêmes actions, pour l'adresse e-mail.

SELECT * FROM "Utilisateur" u
WHERE u.id <> :id AND u.email = :email
LIMIT 1;

Lire R9. Vérifier qu'un matricule de la fonction publique est libre

Quand : Carrière d'un personnel (fiche enseignant, nouvelle attestation).

SELECT * FROM "Utilisateur" u
WHERE u.id <> :id AND u.matricule = :matricule
LIMIT 1;

Lire R10. Professeurs actifs qui enseignent dans l'année

Quand : Ouverture d'une séquence : ces professeurs reçoivent une notification.

SELECT DISTINCT p.id
FROM "Matiere" m
JOIN "Classe" c ON c.id = m."classeId"
JOIN "Utilisateur" p ON p.id = m."professeurId"
WHERE c."anneeId" = :anneeId AND p.role = :role AND p.actif = true;

Ajouter

Ajouter R11. Créer un compte

Quand : Nouvel enseignant (POST /api/utilisateurs), avec le mot de passe provisoire « password » ; amorçage d'une base vide (Directeur et SG).

INSERT INTO "Utilisateur" (id, nom, prenom, telephone, email, "motDePasse", role, actif,
  "doitChangerMotDePasse", discipline, sexe, matricule, grade, fonction, "datePriseService",
  "dateEntreeFonctionPublique", "acteNomination", "creeLe", "majLe")
VALUES (:id, :nom, :prenom, :telephone, :email, :motDePasse, :role, :actif,
  :doitChangerMotDePasse, :discipline, :sexe, :matricule, :grade, :fonction, :datePriseService,
  :dateEntreeFonctionPublique, :acteNomination, :creeLe, :majLe);

Modifier

Modifier R12. Mettre à jour un compte

Quand : Modifier la fiche d'un enseignant ou sa carrière, le désactiver ou le réactiver, réinitialiser son mot de passe ; Mon profil (dont la civilité) ; changer son mot de passe ; désapprobation qui remet l'état précédent.

UPDATE "Utilisateur"
SET nom = :nom, prenom = :prenom, telephone = :telephone, email = :email,
    "motDePasse" = :motDePasse, role = :role, actif = :actif,
    "doitChangerMotDePasse" = :doitChangerMotDePasse, discipline = :discipline,
    sexe = :sexe, matricule = :matricule, grade = :grade, fonction = :fonction,
    "datePriseService" = :datePriseService, "dateEntreeFonctionPublique" = :dateEntreeFonctionPublique,
    "acteNomination" = :acteNomination, "majLe" = :majLe
WHERE id = :id;

Hibernate réécrit toutes les colonnes de la ligne, même celles qui ne changent pas.

Supprimer

Supprimer R13. Supprimer un compte

Quand : Uniquement quand le Directeur désapprouve la création d'un enseignant, et seulement s'il n'a encore saisi aucune note (voir « Compter les notes saisies par un compte »).

DELETE FROM "Utilisateur" WHERE id = :id;

Ses notifications et les attestations dont il est bénéficiaire partent avec lui ; il n'est plus professeur principal ni professeur des matières (champ remis à vide). La base refuse la suppression s'il est l'auteur de notes, de décisions, de renvois ou d'attestations délivrées.

4. Établissement et barèmes

L'établissement tient sur une seule ligne (id = 1) : ce qui s'imprime en tête des documents, le préfixe des matricules et la moyenne minimale du tableau d'honneur. Les barèmes donnent les grades par matière (GRADE) et les cotes de la moyenne générale (COTE).

Tables : Etablissement, Bareme

Lire

Lire R14. Lire l'établissement

Quand : Paramètres ; en-tête de chaque PDF (bulletins, listes, cartes, attestations, certificats) ; préfixe des matricules à l'inscription d'un élève ; seuil du tableau d'honneur.

SELECT * FROM "Etablissement" WHERE id = 1;

Lire R15. Savoir si l'établissement existe

Quand : Amorçage d'une base vide.

SELECT e.id FROM "Etablissement" e WHERE e.id = 1 LIMIT 1;

Lire R16. Lire les barèmes, triés

Quand : Paramètres (GET /api/baremes).

SELECT * FROM "Bareme" ORDER BY type, min DESC;

Lire R17. Lire tous les barèmes

Quand : Calcul des résultats : relevé de notes, bulletins, statistiques, tableau d'honneur.

SELECT * FROM "Bareme";

Lire R18. Lire un barème

Quand : Avant de le remplacer : l'ancien est gardé dans le journal des décisions pour pouvoir le rétablir.

SELECT * FROM "Bareme" WHERE type = :type;

Lire R19. Compter les barèmes

Quand : Amorçage d'une base vide.

SELECT count(*) FROM "Bareme";

Ajouter

Ajouter R20. Créer l'établissement

Quand : Amorçage d'une base vide (une seule fois).

INSERT INTO "Etablissement" (id, "nomFr", "nomEn", sigle, "sigleEn", "regionFr", "regionEn",
  "departementFr", "departementEn", arrondissement, localite, code, "boitePostale", telephone,
  "prefixeMatricule", "seuilTableauHonneur")

  :arrondissement, :localite, :code, :boitePostale, :telephone, :prefixeMatricule, :seuilTableauHonneur);

Ajouter R21. Ajouter une mention

Quand : Une fois par mention du nouveau barème ; amorçage (barèmes par défaut).

INSERT INTO "Bareme" (id, type, libelle, "libelleLong", min)
VALUES (:id, :type, :libelle, :libelleLong, :min);

Modifier

Modifier R22. Mettre à jour l'établissement

Quand : Paramètres : informations de l'établissement (PUT /api/etablissement, SG) ou moyenne minimale du tableau d'honneur (PUT /api/etablissement/tableau-honneur, Directeur ou SG) ; désapprobation.

UPDATE "Etablissement"
SET "nomFr" = :nomFr, "nomEn" = :nomEn, sigle = :sigle, "sigleEn" = :sigleEn,
    "regionFr" = :regionFr, "regionEn" = :regionEn, "departementFr" = :departementFr,
    "departementEn" = :departementEn, arrondissement = :arrondissement, localite = :localite,
    code = :code, "boitePostale" = :boitePostale, telephone = :telephone,
    "prefixeMatricule" = :prefixeMatricule, "seuilTableauHonneur" = :seuilTableauHonneur
WHERE id = 1;

Supprimer

Supprimer R23. Supprimer un barème entier

Quand : Remplacer le barème des grades ou des cotes (PUT /api/baremes/{type}) ; désapprobation qui rétablit l'ancien. Les nouvelles mentions sont ajoutées juste après.

DELETE FROM "Bareme" WHERE type = :type;

5. Années scolaires et séquences

Une année compte six séquences, deux par trimestre. Une seule année est « en cours » (active) ; c'est elle que l'application utilise quand aucune année n'est choisie.

Tables : AnneeScolaire, Sequence

Lire

Lire R24. Lister les années

Quand : Menu « Année scolaire », page Années et séquences (GET /api/annees).

SELECT * FROM "AnneeScolaire" ORDER BY libelle DESC;

Lire R25. Compter les classes de chaque année

Quand : Page Années et séquences.

SELECT c."anneeId", count(*) FROM "Classe" c GROUP BY c."anneeId";

Lire R26. Compter les inscriptions de chaque année

Quand : Page Années et séquences.

SELECT i."anneeId", count(*) FROM "Inscription" i GROUP BY i."anneeId";

Lire R27. Lire l'année en cours

Quand : Toute requête qui ne précise pas d'année ; création d'une année ; attestation (année imprimée).

SELECT * FROM "AnneeScolaire" WHERE active = true LIMIT 1;

Lire R28. Chercher une autre année en cours

Quand : Activer une année : l'ancienne année en cours est gardée dans le journal.

SELECT * FROM "AnneeScolaire" WHERE active = true AND id <> :id LIMIT 1;

Lire R29. Lire une année par son identifiant

Quand : Année choisie dans le menu, activation, création de classes et de groupes, documents, tableau d'honneur.

SELECT * FROM "AnneeScolaire" WHERE id = :id;

Lire R30. Compter les années

Quand : Amorçage d'une base vide.

SELECT count(*) FROM "AnneeScolaire";

Lire R31. Lire les séquences d'une année

Quand : Avancement de la saisie (tableau de bord).

SELECT * FROM "Sequence" WHERE "anneeId" = :anneeId ORDER BY numero;

Lire R32. Lire les séquences de plusieurs années

Quand : Page Années et séquences.

SELECT * FROM "Sequence" WHERE "anneeId" IN (:anneeIds) ORDER BY numero;

Lire R33. Lire une séquence

Quand : Feuille de notes, élèves sans note, ouverture ou fermeture de la saisie.

SELECT * FROM "Sequence" WHERE id = :id;

Lire R34. Compter les inscriptions d'une année

Quand : Avant de supprimer une année : une année où des élèves sont inscrits ne peut pas être retirée.

SELECT count(*) FROM "Inscription" WHERE "anneeId" = :anneeId;

Ajouter

Ajouter R35. Créer une année

Quand : Nouvelle année (POST /api/annees) ; amorçage.

INSERT INTO "AnneeScolaire" (id, libelle, active, "creeLe")
VALUES (:id, :libelle, :active, :creeLe);

Ajouter R36. Créer une séquence

Quand : Six fois à la création d'une année (numéros 1 à 6, trimestres 1 à 3).

INSERT INTO "Sequence" (id, "anneeId", numero, trimestre, "saisieOuverte")
VALUES (:id, :anneeId, :numero, :trimestre, false);

Modifier

Modifier R37. Mettre à jour une année

Quand : Rendre une année active (POST /api/annees/{id}/activer) ; désapprobation.

UPDATE "AnneeScolaire" SET active = :active, libelle = :libelle WHERE id = :id;

Modifier R38. Désactiver les autres années

Quand : Juste après l'activation d'une année : une seule reste en cours.

UPDATE "AnneeScolaire" SET active = false WHERE id <> :id;

Modifier R39. Ouvrir ou fermer la saisie

Quand : Années et séquences (PATCH /api/annees/sequences/{id}) ; désapprobation.

UPDATE "Sequence"
SET "anneeId" = :anneeId, numero = :numero, trimestre = :trimestre, "saisieOuverte" = :saisieOuverte

Supprimer

Supprimer R40. Supprimer une année

Quand : Uniquement quand le Directeur désapprouve la création d'une année, si aucun élève n'y est inscrit.

DELETE FROM "AnneeScolaire" WHERE id = :id;

6. Spécialités et classes

Les spécialités (Mécanique, Électricité…) servent d'une année sur l'autre. Une classe appartient à une année ; son nom se calcule à partir du niveau, de la spécialité et d'une lettre A, B… quand le niveau et la spécialité comptent plusieurs classes (colonne numero).

Tables : Specialite, Classe

Lire

Lire R41. Lister les spécialités

Quand : Fenêtre Spécialités, formulaire de classe (GET /api/specialites).

SELECT * FROM "Specialite" ORDER BY nom;

Lire R42. Compter les classes de chaque spécialité

Quand : Fenêtre Spécialités (une spécialité utilisée ne peut pas être supprimée).

SELECT c."specialiteId", count(*) FROM "Classe" c
WHERE c."specialiteId" IS NOT NULL
GROUP BY c."specialiteId";

Lire R43. Compter les classes d'une spécialité

Quand : Avant de modifier ou de supprimer une spécialité.

SELECT count(*) FROM "Classe" WHERE "specialiteId" = :specialiteId;

Lire R44. Lire une spécialité

Quand : Création ou modification d'une classe, d'une spécialité ; désapprobation.

SELECT * FROM "Specialite" WHERE id = :id;

Lire R45. Années et niveaux des classes d'une spécialité

Quand : Renommer une spécialité : les classes qui la portent sont renommées, groupe par groupe.

SELECT DISTINCT c."anneeId", c.niveau FROM "Classe" c WHERE c."specialiteId" = :specialiteId;

Lire R46. Lister les classes de l'année

Quand : Page Classes et tous les choix de classe (GET /api/classes) ; copie de l'organisation vers une nouvelle année.

SELECT c.*, s.*, u.*
FROM "Classe" c
LEFT JOIN "Specialite" s ON s.id = c."specialiteId"
LEFT JOIN "Utilisateur" u ON u.id = c."profPrincipalId"
WHERE c."anneeId" = :anneeId
ORDER BY c.niveau, s.nom, c.numero;

Lire R47. Lister les classes d'un professeur

Quand : Un professeur ne voit que les classes où il enseigne (GET /api/classes).

SELECT c.*, s.*, u.*
FROM "Classe" c
LEFT JOIN "Specialite" s ON s.id = c."specialiteId"
LEFT JOIN "Utilisateur" u ON u.id = c."profPrincipalId"
WHERE c."anneeId" = :anneeId
  AND EXISTS (SELECT 1 FROM "Matiere" m WHERE m."classeId" = c.id AND m."professeurId" = :professeurId)
ORDER BY c.niveau, s.nom, c.numero;

Lire R48. Lister les classes de l'année par niveau et nom

Quand : Statistiques de l'établissement, tableau d'honneur.

SELECT * FROM "Classe" WHERE "anneeId" = :anneeId ORDER BY niveau, nom;

Lire R49. Lire des classes choisies

Quand : Bulletins de classes entières (POST /api/documents/bulletins).

SELECT * FROM "Classe" WHERE id IN (:ids) ORDER BY niveau, nom;

Lire R50. Lire plusieurs classes

Quand : Création ou modification d'un groupe (ses classes) ; désapprobation.

SELECT * FROM "Classe" WHERE id IN (:ids);

Lire R51. Lire une classe

Quand : Fiche, modification ou suppression d'une classe ; liste et relevé d'une classe ; résultats ; inscription d'un élève.

SELECT * FROM "Classe" WHERE id = :id;

Lire R52. Vérifier qu'une classe est de l'année

Quand : Création d'une matière.

SELECT count(*) FROM "Classe" WHERE id = :id AND "anneeId" = :anneeId;

Lire R53. Classes qui partagent les lettres A, B…

Quand : Création, modification ou suppression d'une classe : les classes du même niveau et de la même spécialité sont renommées.

SELECT * FROM "Classe" c
WHERE c."anneeId" = :anneeId AND c.niveau = :niveau
  AND ((:specialiteId IS NULL AND c."specialiteId" IS NULL) OR c."specialiteId" = :specialiteId)
ORDER BY c.numero, c.nom;

Lire R54. Plus grand numéro du groupe

Quand : Nouvelle classe : elle prend le numéro suivant (lettre suivante).

SELECT coalesce(max(c.numero), 0) FROM "Classe" c
WHERE c."anneeId" = :anneeId AND c.niveau = :niveau
  AND ((:specialiteId IS NULL AND c."specialiteId" IS NULL) OR c."specialiteId" = :specialiteId);

Lire R55. Classes dont des professeurs sont principaux

Quand : Page Enseignants.

SELECT * FROM "Classe" c WHERE c."anneeId" = :anneeId AND c."profPrincipalId" IN (:professeurIds);

Lire R56. Compter les inscriptions d'une classe

Quand : Avant de supprimer une classe : une classe avec des élèves ne peut pas être supprimée.

SELECT count(*) FROM "Inscription" WHERE "classeId" = :classeId;

Ajouter

Ajouter R57. Créer une spécialité

Quand : Fenêtre Spécialités (POST /api/specialites) ; désapprobation d'une suppression.

INSERT INTO "Specialite" (id, nom, "nomEn", "creeLe") VALUES (:id, :nom, :nomEn, :creeLe);

Ajouter R58. Créer une classe

Quand : Nouvelle classe (POST /api/classes) ; nouvelle année avec reprise de l'organisation ; désapprobation d'une suppression.

INSERT INTO "Classe" (id, "anneeId", nom, "nomEn", niveau, numero, "specialiteId", "profPrincipalId")
VALUES (:id, :anneeId, :nom, :nomEn, :niveau, :numero, :specialiteId, :profPrincipalId);

Modifier

Modifier R59. Renommer une spécialité

Quand : PUT /api/specialites/{id} ; désapprobation.

UPDATE "Specialite" SET nom = :nom, "nomEn" = :nomEn WHERE id = :id;

Modifier R60. Mettre à jour une classe

Quand : Modifier une classe (PUT /api/classes/{id}) ; renommage automatique des classes voisines (lettres) ; désapprobation.

UPDATE "Classe"
SET "anneeId" = :anneeId, nom = :nom, "nomEn" = :nomEn, niveau = :niveau, numero = :numero,
    "specialiteId" = :specialiteId, "profPrincipalId" = :profPrincipalId
WHERE id = :id;

9. Élèves, inscriptions et renvois

Un élève a une fiche (Eleve) et une inscription par année (Inscription), dans une classe. Les notes et les renvois portent sur l'inscription : c'est ce qui permet de réinscrire un élève l'année suivante sans perdre son historique. Le matricule est attribué par un compteur.

Tables : Eleve, Inscription, Renvoi, Compteur

Lire

Lire R92. Lister les élèves de l'année

Quand : Page Élèves, élèves renvoyés, réinscriptions (GET /api/eleves). Les conditions entre crochets ne sont ajoutées que si le filtre est donné : statut (ACTIF par défaut, RENVOYE ou TOUS), classe, recherche.

SELECT i.*, e.*, c.*, a.*
FROM "Inscription" i
JOIN "Eleve" e ON e.id = i."eleveId"
JOIN "Classe" c ON c.id = i."classeId"
JOIN "AnneeScolaire" a ON a.id = i."anneeId"
WHERE i."anneeId" = :anneeId
  AND i.statut = :statut                      -- [statut]
  AND c.id = :classeId                        -- [classe]
  AND (lower(e.nom) LIKE :motif ESCAPE '\'    -- [recherche : « %texte% »]
    OR lower(e.prenoms) LIKE :motif ESCAPE '\'
    OR lower(e.matricule) LIKE :motif ESCAPE '\'
    OR lower(e."matriculeNational") LIKE :motif ESCAPE '\')
ORDER BY c.niveau, e.nom, e.prenoms;

14. Suppressions en cascade

Les clés étrangères décident de ce que fait la base quand on supprime une ligne référencée : elle supprime aussi les lignes qui en dépendent (cascade), vide le champ qui la désigne (mise à vide), ou refuse la suppression. L'application vérifie la plupart de ces refus avant d'agir, pour donner un message clair.

Dans l'application, les suppressions directes sont limitées : spécialité, classe vide, groupe vide, matière (avec confirmation si elle a des notes), note effacée, compétence vidée, barème remplacé, rattachement d'une classe à un groupe. Les élèves, inscriptions, comptes et années ne sont supprimés que lorsque le Directeur désapprouve leur création, et seulement si rien n'en dépend encore.

15. Opérations en plusieurs requêtes

Une action de l'utilisateur déclenche souvent plusieurs requêtes, dans une seule transaction : si l'une échoue, aucune n'est gardée. Quelques exemples, dans l'ordre d'exécution :

Inscrire un élève

  1. Lire l'établissement (préfixe des matricules) et la classe.
  2. Attribuer le numéro suivant du compteur des matricules.
  3. Créer la fiche de l'élève, puis son inscription dans la classe.
  4. Consigner la décision dans le journal.

Enregistrer une feuille de notes

  1. Lire la matière et la séquence (la saisie doit être ouverte).
  2. Vérifier que les élèves sont des inscriptions actives de la classe.
  3. Pour chaque élève : lire sa note, puis l'ajouter, la changer ou l'effacer.
  4. Lire la compétence visée, puis l'ajouter, la changer ou l'effacer.

Créer une classe

  1. Lire l'année et la spécialité.
  2. Lire les classes du même niveau et de la même spécialité, et le plus grand numéro.
  3. Créer la classe, puis renommer les classes voisines si elles prennent une lettre.
  4. Consigner la décision.

Supprimer une classe

  1. Lire la classe et compter ses inscriptions (il ne doit y en avoir aucune).
  2. Lire ses matières et les supprimer une à une.
  3. Supprimer la classe, puis renommer les classes voisines.
  4. Consigner la décision.

Ouvrir une séquence

  1. Lire la séquence et la mettre à jour (saisie ouverte).
  2. Consigner la décision.
  3. Lire les professeurs actifs qui enseignent dans l'année et leur envoyer une notification.

Créer une année en reprenant l'organisation

  1. Créer l'année et ses six séquences ; si elle devient l'année en cours, désactiver les autres.
  2. Lire les groupes et les classes de l'année copiée ; créer les groupes, les classes, leurs rattachements et les matières.
  3. Consigner la décision.

Délivrer une attestation

  1. Mettre à jour la carrière du bénéficiaire (requête précédente, depuis la même fenêtre).
  2. Lire l'année en cours, l'établissement, le bénéficiaire et le Directeur.
  3. Attribuer le numéro suivant du compteur « attestation-<année> ».
  4. Enregistrer l'attestation.

Désapprouver une décision

  1. Lire la décision (moins de 4 semaines, encore approuvée).
  2. Défaire l'action à partir des données gardées dans la colonne annulation : suppression de ce qui a été créé, remise des valeurs précédentes, recréation de ce qui a été supprimé ; les vérifications (notes saisies, élèves inscrits) peuvent tout refuser.
  3. Mettre à jour la décision (désapprouvée, motif, auteur, date).
  4. Envoyer une notification au Surveillant Général.

16. Démarrage : migrations et amorçage

Migrations Flyway

Au démarrage, Flyway applique les migrations qui manquent, dans l'ordre, et les note dans flyway_schema_history. Le schéma n'est jamais modifié par Hibernate. Les quatre premières migrations viennent de l'ancienne API Node (Prisma) ; sur une base qu'elle avait créée, Flyway part de la version 4 sans les rejouer.

FichierContenu
V1__init.sqlTables d'origine, énumérations, clés étrangères et index
V2__specialites_decisions.sqlSpécialités et numéro des classes (lettres A, B…), journal des décisions
V3__annulation_decisions.sqlDonnées d'annulation des décisions (JSON)
V4__notifications.sqlNotifications
V5__entete_carriere_attestations_tableau_honneur.sqlSigle anglais et seuil du tableau d'honneur, carrière des personnels, attestations

Amorçage d'une base vide

Lancée avec l'option --amorcer, l'API remplit une base vide, en sautant ce qui existe déjà :

  1. l'établissement (« Savoir si l'établissement existe », puis « Créer l'établissement ») ;
  2. les barèmes par défaut (« Compter les barèmes », puis « Ajouter une mention » pour chacune) ;
  3. l'année en cours et ses six séquences (« Compter les années », « Créer une année », « Créer une séquence ») ;
  4. les comptes du Directeur et du Surveillant Général (« Savoir si un compte de ce rôle existe », puis « Créer un compte »).
